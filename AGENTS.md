# AGENTS.md

Project instructions for AI coding agents working in this repository.

## Overview

A static single-page site: a curated catalog of films, series and documentaries about computers, technology and AI. No build step, no dependencies, no server. GitHub Pages just serves the repo root.

Run locally:

```bash
python -m http.server 8000
# then open http://localhost:8000
```

## Structure

- `index.html` — page markup, `<template id="tpl-catalog">` inline component template. Five blocks are GENERATED by `gen_pages.py` (edit via markers, never by hand): the theme head-script (`<!-- begin:theme-script -->` … `<!-- end:theme-script -->`), the static JSON-LD (`<!-- begin:index-ld -->` … `<!-- end:index-ld -->`), the no-JS catalog list (`<!-- begin:catalog-noscript -->` … `<!-- end:catalog-noscript -->`), the catalog-last-updated widget (`<!-- begin:last-updated -->` … `<!-- end:last-updated -->`) and the Yandex.Metrika snippet (`<!-- begin:metrika -->` … `<!-- end:metrika -->`, single source `gen_pages.METRIKA_SCRIPT`)
- `films/<imdbId>/index.html` — one static SEO page per record (generated; slug is `<id>-<title-en-slug>`, id falls back to `kp-<kpId>` when there is no imdbId). Each page embeds its own record + related titles as `window.FILM_PAGE` and does NOT load `js/data.js`
- `js/data.js` — the catalog (`window.CATALOG`, array of items, each with `desc.ru`/`desc.en`); single source of truth
- `js/catalog.js` — GENERATED by `tools/gen_pages.py` from `js/data.js`: same catalog without `desc` (main page doesn't need it); never edit by hand
- `js/i18n.js` — translations (`window.I18N`), keys for both `ru` and `en`
- `js/app.js` — Vue 3 app (global prod build in `js/vue.global.prod.js`), all filtering/sorting/i18n/theme logic
- `js/film.js` — Vue 3 film-page app (shared by all `films/*` pages; same lang/theme/i18n behavior as `app.js`, uses `window.FILM_PAGE`, does NOT load `js/data.js`)
- `js/common.js` — shared helpers (`window.ITMoviesCommon`): slug/URL builders, lang & theme resolution, rating formatting, storage wrappers, error handler (used by both `app.js` and `film.js`)
- `js/*.min.js` — GENERATED by `tools/gen_pages.py` (minified copies of `i18n.js`/`common.js`/`app.js`/`film.js`); the pages reference the `.min.js` files, never edit by hand
- `css/style.css` — all styling, wrapped in `@layer reset, tokens, base, components, utilities`; CSS variables for theming plus the spacing/radius/z-index/outline/container scale (see **CSS contract** below)
- `static/` — images, fonts, posters (`static/posters/*.webp`)
- `tools/` — local Python helper scripts (tracked in git):
  - `lib.py` — shared helpers (catalog/i18n/slug/genres parsing, `SITE_BASE`) used by the scripts below
  - `verify.py` — integrity checker (source of truth; verifies generated pages are fresh, theme/JSON-LD/noscript/metrika blocks are in sync, JS↔Python slug and related parity, `js/catalog.js` and `js/*.min.js` fresh, regenerates `sitemap.xml` and `robots.txt` only when stale, `--no-write` = check-only, `--strict` = missing Node fails the run, requires `.nojekyll`)
  - `css_diff.py` — computed-style oracle: `capture --out <file>` writes a per-element snapshot of every page/width/theme, `compare <file>` diffs it and exits 1 on any difference (`--ignore-token-deltas`, `--schemes dark`). A scoped compare — any `--pages`/`--widths`/`--height`/`--scroll`/`--schemes` on a two-file compare — exits **2** unless `--accept-partial-scope` is passed, and then its exit 0 certifies the kept subset only and names every excluded record; a scope that keeps nothing also exits 2, never 0. The only accepted evidence that a stylesheet change moved nothing.
  - `gen_pages.py` — generates `films/*` pages from `js/data.js` + `js/i18n.js` (each embeds `window.FILM_PAGE` and the Yandex.Metrika snippet), generates `js/catalog.js` and `js/*.min.js`, and injects the theme, JSON-LD, no-JS, last-updated and Metrika blocks into `index.html` / `404.html` via markers
  - `gen_posters.py` — generates the poster variant ladder in `static/posters/` and squeezes any original >= 100KB (idempotent; run after adding new posters — `tools/verify.py` checks every catalog poster has the whole ladder, all rungs at their rung width and at the source aspect ratio; the widths come from `lib.POSTER_VARIANT_WIDTHS`, never from a constant here)
  - `smoke.js` — node smoke harnesses (app.js / slug parity / film.js / related parity, each also run against `.min.js` via `--min`) driven by `verify.py`
  - `pw_kp.py` — Kinopoisk search + rating lookup via Playwright (kpId, kpRating, kpVotes, IMDb sub-rating)
  - `kp_votes.py` — bulk Kinopoisk vote-count collector over existing kpId values (resume via `_tmp/kp_votes.json`, `--limit`/`--reset-null`)
  - `poster_crop.py` — measures poster crop with no browser: both quantities (`PROXY = |w/h − 2/3|` and `DISCARDED_AREA = 1 − (bw/scale)(bh/scale)/(sw·sh)`, `scale = max(bw/sw, bh/sh)`) from real Pillow dimensions, prints median/p90/max for each, how many posters are exactly 2:3 and how many lose anything, the worst five by **each** quantity, and every poster over `DISCARDED_AREA_CEILING`. Runnable and importable (`--dir`, `--box W H`, `--ceiling`, `--json`, `--quiet`); exits 1 when the bound is exceeded, so `verify.py` block 4c calls it instead of re-deriving the arithmetic. **The library does not meet the bound: 54 of 154 posters. Since 2026-09-28 `verify.py` block 4c REPORTS that and no longer fails on it, by the human partner's ruling — this tool still exits 1, and the bound is still 0.02.** See the poster section below for why the gate was silenced and what it must never be read as.
  - `e2e.py` — optional real-browser smoke (Playwright + chromium, local only, NOT part of the verify gate): main-page filter/lang, film-page theme/share/related, bootstrap fallback. On the related cards it asserts the two things only a browser can see — the **rendered** `.rc-poster` box is 2:3, and the file `currentSrc` names is a real file on disk — and *reports* the discarded area of those files using `poster_crop.py` without gating on it. The old `POSTER_CROP_CEILING = 0.16` is gone; the bound belongs to `poster_crop.DISCARDED_AREA_CEILING` — see the poster section
  - `show_types.py` — prints every record with its line number in `js/data.js`

## CSS contract

`css/style.css` is the only stylesheet and it is wrapped in cascade layers. These rules are a contract, not a report; the full Stage 2a record (all 57 tokens, layer rule counts, every sanctioned literal, the re-baseline cost) is `docs/superpowers/specs/2026-09-26-ui-redesign-design.md` §8, and the Stage 2b record is §9 of the same file — but that path is **gitignored**, so this section is the copy that ships.

- **Layer order is `reset, tokens, base, components, utilities`**, declared in one ordered statement on line 1. Put a new rule in the layer it belongs to. Never append unlayered: an unlayered rule outranks every layered one, so one stray block silently defeats the whole system.
- **Tokens, not literals.** Spacing is `--space-1`…`--space-9` plus `--space-0-2`/`--space-0-35`/`--space-1-25`/`--space-2-25`/`--tap`; radius is `--radius-xs|s|m|l|xl|circle|pill`; stacking is `--z-raised`/`--z-modal`/`--z-skip`. 58 tokens are declared and all 58 are referenced — do not add a token you do not use, and do not inline a value a token already carries. (`--space-9: 4.5rem` is the 72px section rhythm added by the 2026-09-29 dark editorial redesign; measured on that tree: 100 declarations, 58 unique, 58 referenced, 0 orphans.)
- **`verify.py` block 6d caps that, and it compares by value, not by text.** `STYLE_LITERAL_CEILING = {"spacing": 6, "radius": 0, "z-index": 0}` with `STYLE_LITERAL_SCOPE = {"spacing": "token", "radius": "any", "z-index": "any"}`. Every value is resolved to px and compared against token values resolved to px, so `12px` and `0.75rem` are caught as the same regression. A bare length in a box-spacing property (`margin*`, `padding*`, `gap*`, `inset*`, `scroll-margin*`, `scroll-padding*`, `top`/`right`/`bottom`/`left`), in `border-radius`, or in `z-index` fails the gate; a `calc()`/`min()`/`max()` of constant lengths is resolved and compared too, and a `clamp()` with a viewport term is not, because it is not constant. Use `var(--token)`.
- **The `radius` and `z-index` ceilings are absolute 0 and must never be raised.** Their scales are closed: all 7 radii in circulation are tokenised, and there are exactly 3 z-index tokens and exactly 3 uses. Any bare value in either family means a *token is missing*, and the fix is the token. The `spacing` scale is open — `0.1em` badge padding, `15vh` boot centring, `-50px`, `-6px` are legitimate and no token can or should cover them — so spacing keeps a real ceiling, currently **6**: `4px` ×2 (`--space-1`) and `8px` ×4 (`--space-2`), all px-vs-rem and therefore equal only at a 16px root. Those 6 and the 25 off-scale values are named on every run; a new one must be tokenised, or the ceiling raised in the same change, with its name and reason. The `rem` base is the root `font-size`: `verify.py` reads it from `css/style.css`, falls back to the CSS initial value, and prints which on every run. Box sizing (`width`, `height`, `min-*`, `max-*`, `flex-basis`) is not tokenised at all and is outside the gate.
- **There is one canonical breakpoint scale — `xs ≤575 / sm ≥576 / md ≥768 / lg ≥1024 / xl ≥1200` — and it is written in exactly one place: `lib.BREAKPOINT_SCALE = (575, 576, 768, 1024, 1200)`.** The px values a `@media` condition may use are **`lib.CSS_MEDIA_EDGES`, which is derived from that tuple, not listed beside it**: every boundary, plus every boundary minus one for the `max-width` form that expresses "below the next tier" — so `{574, 575, 576, 767, 768, 1023, 1024, 1199, 1200}`. Deriving it is the point: a hand-listed set silently omitted `576` once, which meant the gate rejected a correct `sm`-tier rule while offering "add it to `lib.CSS_MEDIA_EDGES`" as the remedy — i.e. telling you to edit a constant that exists to be derived. **`verify.py` 6f now checks the relationship instead of trusting it**, and fails if `CSS_MEDIA_EDGES` is not a superset of `BREAKPOINT_SCALE`, or if `BELOW_MD_MAX` (the poster `sizes` breakpoint, itself derived as `BREAKPOINT_SCALE[2] - 1`) is not an admitted edge. The poster `sizes` value is the single source `lib.poster_sizes()`, feeding 308 generated occurrences. `verify.py` enforces the whole chain: **6e** polices the emitted `sizes` values against `lib.poster_sizes()` (the condition *and* the slot sizes), and **6f** parses every `@media` and `@container` prelude in the stylesheets named in `verify.CSS_MEDIA_FILES` and asserts the width edges it finds are a **subset** of `CSS_MEDIA_EDGES`, reporting every value found and every value rejected. Two properties of 6f are deliberate and must not be "tidied": the relation is a **subset, not equality** — 1024 and 1200 are permitted while unused because Stage 3 adds the `lg` and `xl` tiers, and a gate that must be edited before a legitimate tier can be added is a gate that gets edited carelessly; and its scope is **the stylesheet, not the repository** — a bare 480 or 950 is equally at home in prose (this file, `tools/css_diff.py`'s own docstring, the gitignored spec) and in an SVG path (`static/share.svg`), so a repo-scoped gate would report violations in files that are already correct and its own remedy ("add the value to `lib.CSS_MEDIA_EDGES`") would not apply to them at all. To use a value that is missing on purpose, add a boundary to `lib.BREAKPOINT_SCALE` — never to `CSS_MEDIA_EDGES` and never to 6f. A rejected edge's own failure message says the same thing, and it is worth reading: a gate that names the wrong file as the remedy teaches the wrong lesson.
- **6f also pins three things a re-key must not disturb,** and each carries its reason in the failure message: exactly one `@media (prefers-color-scheme: dark)` and exactly one `@media (prefers-reduced-motion: reduce)`; exactly one `@container scroll-state(scrollable: top)` **with its original condition** — it is a container query, not a width query, so any tool that re-keys "all breakpoints" must leave it alone and this is what proves it did; and **three separate blocks carrying `max-width: 575px`**. It also refuses a width edge in any unit it cannot resolve to px (`60em`), because a width nothing in the project can check is a width nothing checks.
- **The three `max-width: 575px` blocks must stay three, and merging them is a layout change, not tidying.** They are `:1501` (`.featured-grid`, the carousel), `:1992` (`.related ul`) and `:2146` (`.profile`) — 491 and 154 physical lines apart, 645 from first to last, in three different components. `480` and `525` both collapse onto `575`, and **media conditions cannot read a custom property**, so the spec's "emit each boundary once" is realised as a canonical value set plus a gate rather than as one definition; there is no way to write the condition once. Merging the blocks moves rules across 645 lines of source order, and Stage 2a deliberately kept every media query on its original line precisely so that source order could not shift. If a single xs block ever *is* the right answer, that is a deliberate decision recorded in the spec, and `verify.CSS_MEDIA_XS_BLOCKS` changes with it.
- **The retired edges `480 / 525 / 720 / 721 / 950` do not exist in `css/style.css` and must not come back.** `css_diff.py` had a structurally blind probe set because the re-key could not be observed at any of its five widths; the ad-hoc set could otherwise be reintroduced one literal at a time with every other check green, since 6d examines only box-spacing properties and 6e only the `sizes` attribute. 6f closes that. A mention of a retired edge in prose is not a violation — 6f parses preludes, it does not grep text — but prose must mark it as retired so the next reader does not take it for a live condition.
- **There is a 1 CSS px seam in the viewport axis and it is not a bug you can gate away.** The conditions tile **every integer width** 0–1500 with no gap and no overlap, but the open interval **(767, 768)** matches no width block — **1.00 CSS px** wide, arithmetically, in the re-keyed tree and in the pre-re-key tree alike, which had the identical seam at (720, 721). It is unreachable from every harness in this project: **Playwright refuses a fractional emulated viewport outright** (`Browser.setWindowBounds: Invalid parameters`, on both `new_context` and `set_viewport_size`), so no probe here can ask the question. **Which way a browser rounds a genuinely fractional viewport is not established by this project and is not claimed** — one earlier note said "truncated (measured: 720.5 → 720)" and that measurement was reading its own `int(w)`; another said the opposite direction. If you want the direction, you need a probe that can express a fractional width at all. 6f prints the seam as **information, not as a failure**, and says why: a gate asserting perfect tiling would fail on a property CSS does not have, and it would fail on a correct stylesheet.
- **The 481–575 band is observable only because `/about.html` is in `css_diff.DEFAULT_PAGES`, and nothing gates that pairing.** The `.profile` rules live in the `≤575px` block, which only that page renders, so move `.profile` to another page or drop `/about.html` from the default set and widths 520 and 550 go on observing a band no record in the snapshot carries — with no width in the set noticing, because a width is not a sample of a band, it is the only thing the harness observes. `verify.py` has no machinery for "is the page that carries this selector in the probe set", so this is a recorded dependency, not a gate: re-probe a band by moving the page, not just the widths.
- **Re-baseline before you touch the stylesheet, every time.** `python tools/css_diff.py capture --out _tmp/<stage>-base.json` → edit → `capture --out _tmp/<stage>-after.json` → `compare _tmp/<stage>-base.json`. A baseline is valid only for the tree that produced it. A green compare is evidence only when the harness prints `EXIT 0 IS UNQUALIFIED` (with `--ignore-token-deltas`, nothing was set aside); a claim about both themes needs a `--schemes dark` capture, and the focus pass is the only way the harness can observe the 13 `outline` declarations. **A scope flag on a two-file compare cannot certify anything, and how it fails depends on what the excluded records hold.** The flags filter the records the two files already hold instead of re-capturing, so a scoped compare certifies a subset. If the excluded records are individually clean the run prints `SCOPED COMPARISON, NOT A CERTIFICATION` and **exits 2**; if any excluded record differs it takes the stronger branch, prints `A DIFFERENCE IS HIDDEN INSIDE THE SCOPE` with each offender named, and **exits 1** — and `--accept-partial-scope` explicitly does not apply there, because it can only downgrade a refusal into a partial pass, never turn a difference into one. **To assert that a subset of widths did not change, capture a snapshot pair containing only those widths and compare it unscoped, so the compare is a whole-file pass over a file that holds nothing else; do not scope a wider snapshot.** That is the only form in which exit 0 means the claim, and it is the form Stage 2b used to certify the five control widths: a dedicated 5-width, 4-page, light+dark pair compared with no flags gave `IDENTICAL -- 40 record(s)` and `EXIT 0 IS UNQUALIFIED`, where the same five widths reached by `--pages`/`--widths` on the 88-record pair exited 1 because the six widths it excluded genuinely differ. Read the excluded-record list whenever a scope is used.
- **The related card `.rc` has exactly ONE hand-maintained source, `gen_pages.RC_CARD` in `tools/gen_pages.py`, and it is a Vue template, not a static fragment.** `gen_pages.render()` produces two renderings of it and both are what the page ships: the no-JS card in `<noscript>`, resolved by `rc_card_html()` through `rc_values()`, whose `RC_STATIC` table is keyed by the *exact expression text* the template binds (`relatedTitle(r)`, `hasRating(r.kpRating)`, `t.kpShort`, …); and the client card, emitted verbatim into every film page as `window.FILM_RC_CARD = "<escaped template>"`, which `js/film.js` splices into `FILM_TEMPLATE` as `${RC_CARD}`. **The client keeps owning every value it displays** — what crosses into the page is a template with `{{ }}` and `:` bindings in it, never interpolated text — so switching a film page to `en` still re-renders the card in English; that is measured, not assumed. The table and the template **close on each other**: an expression `RC_CARD` binds that `RC_STATIC` has no value for, or a `RC_STATIC` entry the template no longer binds, raises out of the generator rather than letting one side fall back to a value of its own. Edit the card in `RC_CARD` and re-run `python tools\gen_pages.py`; never hand-edit a card in `js/film.js` (that file no longer has one) and never hand-edit `window.FILM_RC_CARD` in a committed page.
- **`verify.py` 6g compares the MARKUP of those two renderings, and it is blind to the source by construction — read it as "the two renderings of this source agree", never as "this card is correct".** Both sides are rendered **in memory** from one `gen_pages.render()` call, the client side decoded out of the same string with `json.JSONDecoder().raw_decode`, so nothing here reads a committed `films/*/index.html`: that is deliberate, and it is the only thing in the project that can see a generator-side change (a deleted element, a broken renderer, a mangled emission), where reading the pages would leave 6g green and leave only the freshness check to notice. It compares depth-first `(tag, classes, parent-index)` lists — same nine nodes, same classes, same nesting — and no attribute *value* participates. **What one source costs is the other half of the old gate: a change made in `RC_CARD` moves both renderings at once and is invisible to 6g, and no gate over a single source can see it, because the source is exactly what 6g treats as the truth.** Three checks cover the ways that can go wrong quietly, all inside 6g: a second copy of `<a class="rc"` in any hand-maintained file is an error (`RELATED_CARD_SOURCE_SCOPE`, which is why a card pasted back into `js/film.js` fails); Cyrillic anywhere in the client card is an error, because a literal is Russian whatever `lang` says; and every class the card puts on an element must exist in `css/style.css`, which is the one file that did not come out of `RC_CARD` and is therefore the only independent witness left that the card and its styling still meet. A class renamed in `RC_CARD` used to be caught by the two-copy comparison and is caught now only by that last one.
- **`.featured-card` on the main page and `.rc` on a film page are INTENTIONALLY two different cards. Do not unify them as a cleanup.** Measured inventories: `.featured-card` (the `<a class="featured-card">` in `index.html`'s featured template — line numbers drift, grep the selector) has an accent top border, its own 14px/700 title with an alt-title line under it, a `★` + year and a first-genre row, and a `70px minmax(0,1fr)` grid; `.rc` has none of those. The spec's §1.4 property table records that *every* compared property differs, and it is the reference for that claim. Merging them is a visible design change on the main page and on 154 film pages, it was explicitly declined for this stage, and it belongs with the Stage 3 work that owns the featured block, the table and the grids. The parity gate covers `.rc` only and is not evidence about `.featured-card`; their divergence is the intended state, not an unclosed gap.
- **The 2026-09-29 featured-card rework shipped the approved design — six cards (2+2+2), an alt-title line, `★` instead of the badge, a 70px poster column — and the hole under a one-line title is gone, fixed by deleting `min-height: 2.5em` rather than by any padding trick.** The card now reads title / alt / (`★` + year, first genre) / ratings. The alt row is the *other* language, by the film page's `altTitleC` rule, and `v-if` hides it when `titleRu === titleEn` — true for **9 of 154** records, all documentaries, so those cards are legitimately 17.5px shorter and `space-between` spreads their slack the same way. **The hole:** `min-height: 2.5em` reserved a second title line that a one-line title never filled, leaving **21.5px** between title and alt; with it gone and `.featured-card-copy { align-content: space-between }` the gap reads **4px** in a row whose titles all fit one line and **9.8px** in a row holding a two-line title (17.5px of slack over three gaps). **The poster column does not drive the height** — the box is content-driven by the copy column and the poster is `width/height: 100%` + `object-fit: cover`, so it stretches to the row: narrowing 94 → 70 changes the picture, not the box. Measured on the committed tree with no injection (`_tmp/shoot_after.py`): `@1280` card **135**, copy **228**, poster **70×109**, gap **4**; `@576` cards **152 and 135**, copy **144.5**, poster **70×126**, gaps **9.8 and 4**; - **The `.related ul` md column count is pinned, not derived, and the pin must stay below the base rule — this is the same source-order trap as standing defect (1), and it bit this stage's first attempt.** (Defect (1) is now fixed by a *floor* rather than by winning, so this one cannot be fixed that way: a `grid-template-columns` floor has no min/max counterpart, and the pin below the base rule is the only correct placement.) The base `.related ul` is `repeat(auto-fill, minmax(220px, 1fr))`; measured container width is `min(viewport - 55px, 1040px)` and the cap is reached at viewport ≥ 1095. Under that floor alone, 4 related items compute **3 columns on viewport 768–958** (`n = floor((C + 8) / 228)`, 3 tracks while `676 ≤ C < 904`) and strand the 4th card alone in a second row spanning a third of the width; at ≥ 959 they compute 4 and are fine. - **There are two quantities called "crop", they are not interchangeable, and the one this project was tuning was not the one that costs the reader anything.** `object-fit: cover` discards image **AREA**: `DISCARDED_AREA = 1 − (bw/scale)·(bh/scale)/(sw·sh)` with `scale = max(bw/sw, bh/sh)`. What `e2e.py` used to measure and call "crop" was `PROXY = |w/h − 2/3|`, an **aspect-ratio deviation**, which is a different and much smaller number. - **The two rankings name the same five posters and do not agree on their order, and the disagreement is the finding.** `theperipheral` (338×600) discards **more** area than `hacker` (464×600) while ranking **lower** on the proxy, so a ceiling fitted on the proxy sends you to fix the wrong file first. The reason is that the loss is two different functions: a source wider than 2:3 loses `1 − (2/3)/r` of its area, a taller one loses `1 − 1.5·r`, and for a tall narrow source `cover` scales to fill the width and throws away height hard. **Only 19 of 154 posters are exactly 2:3; the other 135 all discard something, so this is library-wide and not a tail.** The spec's "46 of 154 (29.9%)" is the **proxy** count and understates the area problem by 8 posters — both figures are correct, only one of them describes what a reader loses.
- **`DISCARDED_AREA_CEILING = 0.02` (`tools/poster_crop.py`) is the bound, it bounds the discarded AREA, and the library does not meet it: 54 of 154 posters (35.1%), worst `theimitationgame_film_poster.webp` 491×600 at 0.18534.** `verify.py` block 4c imports the module and, since 2026-09-28, **prints one line per offender by name and no longer adds them to the error list** — the run ends `✅ All good` and exits 0 while all 54 are still over the bound. **Read that green as silence, not as repair: the offenders are listed in the run output under a line that begins `NOT A GATE FAILURE, AND NOT REPAIRED`, and that label is the whole contract.** `python tools\poster_crop.py` still exits 1 on the same tree, and the bound is still 0.02. The reason for the number: 0.02 is not fitted to any sample, it is the one poster-fidelity standard this project has ever declared, and it is applied here to the quantity that costs image. That is a deliberate **tightening, not a translation** — 0.02 on the proxy admits a discarded area of up to 0.0291, and the exact area equivalent of the old standard, `0.02/(2/3+0.02) = 0.02912`, fails 46 instead of 54. The retired `POSTER_CROP_CEILING = 0.16` on the proxy permitted a discarded area of **0.1935**, so **any bound near the current worst would have been the same leniency under a new name** — which is why the bound is 0.02 and not 0.19, and why "raise it until the library passes" is the exact failure this stage exists to end. **That reasoning about the QUANTITY stands untouched and is not what was reversed.** What was reversed is the THRESHOLD's premise: on 2026-09-28 the partner rendered the decision rather than describing it — `_tmp/frame-preview.html`, seven real posters in the boxes as they stood then (96×144 desktop, 84×126 mobile — since 2026-09-29 there is one 104×156 box at every width, see the `RELATED_POSTER_SIZES` bullet), `cover` beside `contain` at 1x, 2x and the mobile box — and ruled that **cover with no frame is the intended rendering and the discarded pixels do not read as damage**, while the bars do (up to 13.3px horizontal for wide sources, 7.4px vertical for narrow ones, measured). Both repairs were declined on that evidence: **framing** (one CSS declaration, zero discarded area on all 154) and **re-encoding** 135 sources to 2:3. So the gate was silenced for the reason that it measures harm the product does not have — **not** by raising the ceiling, and **not** because the library passes. Anyone who wants the gate back must fix the posters, not the constant.
- **The hero is never cropped, at any rung, and the browser now says so on every run.** `.film-poster img` is `height: auto` at a fixed width, so its computed `object-fit` is `fill` and the box takes the fetched file's own ratio: measured 2026-09-28, 240×355.797 at 375 and 320×474.391 at 1280 against the 400×593 rung (0.674536). Its discarded area is 0 by construction, and the ladder's own worst is `theimitationgame_film_poster.webp` at the **96w** rung (96×117, 0.18750) — worse than its source's 0.18534, because each rung's height is rounded independently from a non-integer scale factor (largest rung-vs-source delta measured across all 462 rungs: **+0.00342**). **Do not write a zero-tolerance assertion against a rung's discarded area, and do not mistake a moved rung figure for a crop regression.**
- **`e2e.py` no longer owns a crop number; it defers to `poster_crop.py`, and what it keeps is what only a browser can see.** Its old assertion was a Playwright probe over 4 posters against a ceiling 3.1× above the worst value in its own sample, which is how that ceiling survived a stage. It now computes the same quantity with the same code and asserts nothing about the value, and it checks the rendered box is 2:3 plus that `currentSrc` names a real file on disk. **4 posters is enough for that purpose and not for bounding the library**: bounding the library is `poster_crop.py`'s job over 154 files. The old probe also read the wrong file twice over — it built a bare `new Image()` on the `_400` rung, which is not the rung the browser selected, and `assert_related_posters` read `naturalWidth` on a `srcset` image, which **Chromium density-corrects** (measured: 240×355 reported for the 400×593 rung in a 240px slot; the ratio survives, so the assertion it fed was not wrong, but the numbers it printed were not intrinsic). Concretely, on `films/tt0133093-the-matrix/` the old probe printed proxy `0.0515` for the **400w** file while the browser had actually fetched the **96w** file, whose real discarded area is **0.0694**.
- **The residue, stated plainly, so nobody rediscovers it as a bug.** With only 96/192/400 on the ladder: (a) **the lightbox box is still served by the 400w original** — it has no `srcset` at all, so the 351px and 400px boxes measured above get whatever `src` names, and at 2x DPR the 400px box is served a 400px source; it has no candidates to choose from and no `sizes` to be wrong. (b) **A 3x DPR phone rendering the 240px mobile box needs 720 device px and no candidate that wide exists** — the ladder tops out at the ~405px originals, so every DPR ≥ 2 hero load fetches the full-size poster on every page, which is the largest remaining waste in the image pipeline and is untouched by a correct `sizes`. (c) The 192w rung is under cost scrutiny: it doubles the variant count for a single intermediate step. **Do not speculatively add a 768w rung to fill (b) or a `srcset` to fill (a)** — a variant nothing selects is a file nobody needs, and both of those are a Stage 3 decision that has to come with its own byte measurement. (d) The hero's `sizes` is exact for the two boxes it describes and says nothing about the lightbox, by design; anyone extending the lightbox to a `srcset` needs a second value, and it is a different attribute on a different page.
- **The computed-style diff is NOT empty for this change, and it is informative rather than weak — but read it for what it says.** `sizes` is not a computed style, so an empty diff would have been uninformative; the measured diff is instead **`DIFFERENT -- 10 record(s) changed, 915 element(s) changed, 42 value(s) changed outside per-element props`, process exit 1**, 967 diff lines. All 10 records are the **520/550/575/576/767** widths of the **two probed film pages** — exactly the band where the fetched hero file changes — and every delta is one of **0.1093, 0.1094, 0.25, 1.0** px. The cause is measured, not inferred: the 400w variant's aspect ratio differs from its source's by ~0.07% (405×600 → 400×593, `h/w` 1.481481 → 1.4825), and because the hero img is `height: auto` at a fixed 240px width, the auto height becomes 355.546875 → 355.796875px and everything below it shifts by the same 0.25px. **The box width is 240px in both arms; only the height moves, and it moves because a different file was fetched.** This is the one place where "the rendered result must not change, only which file the browser fetches" is not literally true: it changes by 0.11–0.25 CSS px, below one device pixel at 1x, and `css/style.css` is byte-identical (sha `98b704cf…`). A real overflow test is still required before anyone treats a sub-pixel delta as harmless in general.

## The xs menu: a native `<dialog>`, and the no-JS tier that keeps the anchors

- **The xs navigation is a native `<dialog>` opened with `showModal()`, and it is the only navigation affordance below 576px. Above it, the inline anchor row is the affordance.** One source each: the button is `button.menu-toggle` in `index.html`'s `.tool-buttons`, and the panel is `dialog#nav-dialog` containing `nav.nav.nav--dialog`. The dialog is opened by `app.js`'s `openMenu()`/`closeMenu()` and nothing else — **there is no keydown handler for Esc and no hand-rolled focus trap, because `showModal()` provides the trap, the inertness of the document behind, and Esc.** Do not add either. The one handler that does exist is a `close` listener that syncs `aria-expanded`, because Esc bypasses the app entirely.
- **The nav's three anchors are rendered TWICE in `index.html` — once inline and once inside the dialog — and that duplication is the price of the no-JS guarantee, not an oversight.** The inline copy is `nav.nav:not(.nav--dialog)`; the dialog copy is `nav.nav--dialog`. They are the same three `#`-targets, so with JS on and no-JS both, the page holds two nav landmarks. Only one is ever rendered at a time, which is what `test_nav_tier` asserts.
- **The tier is expressed with `html:not(.js)`, and that is the whole no-JS mechanism.** `index.html:6` runs `document.documentElement.classList.add("js")` from an inline `<head>` script, so `html:not(.js)` is exactly "scripting is unavailable" and needs no JS of its own to evaluate. In the `max-width: 575px` block: `html:not(.js) .menu-toggle { display: none }` and `html:not(.js) .nav:not(.nav--dialog) { display: flex }`. **Measured consequence, and it is the reason this is not a silent trade:** with JS disabled the burger is `hidden` and the inline row renders with all three anchors at **every** width 320–1280. Without those two rules a reader without JavaScript gets a burger that cannot open, and the nav is gone. Deleting them is caught — see the mutation below.
- **The defect this replaced was real but narrower than "the xs tier", and the wrap band is locale-dependent.** The three anchors are 44px tall and `flex-wrap: wrap`, so the third wraps to a second row and is orphaned alone. Measured at every integer width 300–600, both locales, JS on: **`ru` wraps at 305–496 and is one row at 497+; `en` wraps at 300–444 and is one row at 445+.** At 375 both locales are 2 rows with the third anchor (`Документальные 53` / `Documentaries 53`) orphaned — the plan's claim, confirmed — **but the nav is already a clean single row at 520 and 575, which are also `xs`.** So 50px–100px of the xs tier was never broken, and the burger now covers it anyway. That is the accepted cost of a tier boundary at 576 and is stated here so it is not rediscovered as a bug.
- **Without JS the three nav anchors are present, focusable, and already dead: their targets are zero-height.** Each `#movies`/`#series`/`#documentaries` is a `<catalog-table>` custom element that Vue never renders without JS, so with scripting off each measures `0x0` with `childElementCount: 0`, and clicking one sets `location.hash` and scrolls to a zero-height point. The no-JS path that actually works is the generated `<noscript class="no-js-catalog">` list of 154 real film links. **So the xs no-JS nav was three links to nowhere before this change and is three links to nowhere after it — what changed is that they are no longer hidden behind a control that cannot open.** Fixing those targets is out of scope and is not a regression introduced here.
- **The xs page is shorter because the second row is gone, and it is shorter by a different amount per width.** Measured document height, 3 loads each, JS on: **11211 at 375, 11057 at 520, 11039 at 550, 11025 at 575** (spread 0 across loads at every xs width, because the removed row is not `Math.random`-dependent), against 11604–11613 at 576, 12456 at 768, 12044–12062 at 1024, 12003 at 1280. The 576/1024 spreads are the featured-shuffle noise, not this change. **At xs the nav's 2-row 96px box plus the burger's 44px is a net loss of roughly one row; above xs the inline row is unchanged.**
- **`aria-current` is set by one `IntersectionObserver` in `app.js`, and it names the section occupying a band 20%–30% down the viewport, not the one at the top.** `rootMargin: "-20% 0px -70% 0px"` with `threshold: 0`; on each callback it picks the first of the three targets currently in that band and **leaves the previous value alone when the band is empty**, so nothing is marked above the first section rather than flickering to `null`. Measured at 1280 over a 50px scroll sweep: flips at **550 / 5500 / 7850** against geometry-predicted **598 / 5513 / 7853** — correct to within one 50px sample. **An earlier reading of 6600 for the `series` flip was a measurement artifact of a 100px step with a 90 ms settle, not observer lag; re-running at 50px/400ms reproduced 5500, and the observer is not debounced.** The rule `.nav a[aria-current="true"]` is the only visual difference and applies to both nav copies.
- **`.nav a` in `css_diff.FOCUS_TARGETS` was re-pinned to `.nav:not(.nav--dialog) a`, and `FOCUS_TARGETS` grew 19 → 23.** The old entry matched the *first* `.nav a` in the document, which after this change is the inline copy — `display: none` at xs. `el.focus()` on a `display: none` element is a no-op, so `:focus-visible` never matched and the pass failed with "did not match :focus-visible", which is the harness correctly refusing to go green while observing no ring. Three entries were added: `.menu-toggle` (default), `.nav-dialog-close` and `.nav--dialog a` (a new `menu` phase). **The `FOCUS_PASS` also gained a `rendered` guard: an element with a zero-size rect or `visibility: hidden` is recorded as `rendered: false` and skipped rather than counted as a missed ring.** That guard is a *skip, not a pass* — a `display: none` element cannot take focus and has no ring to observe — and **the invariant it used to protect moved to `tools/e2e.py`'s `test_nav_tier`, which asserts the tier behaviourally** rather than inferring it from a focus ring. `.profile-links a` was also added, closing a real gap: it carries an `outline` declaration (`/about.html` only) and was in no target list. A `menu` phase is only run where the burger is rendered, because the dialog cannot be opened above xs.
- **`ui_audit.TAP_TARGETS` was NOT extended, and that is a measured decision, not an oversight.** The new controls clear the target at every width they render at: `.menu-toggle` and `.nav-dialog-close` are **44x44** and `.nav--dialog a` is **44 tall** at 320/375/575 (JS on, measured), so none of them is a tap-target finding, and the xs inline row is `display: none` and correctly contributes nothing. The six `.nav a is 99/101/107/109/157/165 x40` advisory lines are the **desktop** inline row and are byte-identical before and after. **The report in that experiment's two arms was byte-identical — 88 lines, sha `d432b5db77c56e0e` both arms, 0 lines added, 0 removed, 0 multiplicity changes — and both arms read `HARD 2 / ADVISORY 57`, which was that tree's figure. Today's is `HARD 0 / ADVISORY 79`, with the redesign's base `1dcbe22b` at `HARD 0 / ADVISORY 59`; see the ui_audit baseline bullet above.** If a future change makes the burger smaller than 44px, add it to `TAP_TARGETS` then; adding it now would assert nothing and cost coverage honesty.
- **`test_nav_tier` in `tools/e2e.py` is the guard for this whole mechanism, and both mutations are caught by it.** Scenario 12 of 12. It asserts, at 320/375/575/576/768/1280, that **exactly one** navigation affordance is reachable (`burger XOR inline`, never both, never neither), that the xs burger carries `aria-expanded="false"` when closed plus `aria-haspopup="dialog"`, `aria-controls` and an accessible name, that the dialog is a real `:modal` that takes focus, that **no focusable control outside it ever receives focus across a full Tab cycle**, that Esc closes it and returns focus to the burger, and — in a **second browser context with `java_script_enabled=False`**, the first in this project — that the burger is absent and the inline row still carries all three anchors at every xs width. Two mutations, both printed before their verdict was read, both restored with the blob re-checked (`ce92ebc7…` before, `6bfcfc5f…` after): moving the xs rules to `max-width: 767px` → `FAIL test_nav_tier: @576: above xs the inline row is the affordance` (and `test_featured_breakpoints` also fails, correctly); deleting the two `html:not(.js)` rules → `FAIL test_nav_tier: @320 without JS: the burger cannot work, so it must not be shown`. **The second is the one that matters: it is the no-JS regression, and it is loud.**

## CRITICAL rules

- Everything that is NOT data validation must stay compatible with a fully static deployment: no server-side logic, no build step. URL parameters are handled client-side via `URLSearchParams` + `history.replaceState`.
- Do NOT break the contract between `data.js`, `i18n.js` and `app.js`:
  - `titleEn` must be Latin script; `titleRu` is the Russian title
  - `desc` is REQUIRED on every record: `desc.ru` and `desc.en`, both non-empty (used for film pages + SEO meta)
  - `genres` values must come only from the keys defined in `I18N.ru.genres` / `I18N.en.genres`
  - any new user-facing string needs keys in BOTH `ru` and `en`
  - if `poster` is set, the file must exist under `static/posters/...webp`
  - poster filenames must match `^[a-z0-9_]+\.webp$` (lowercase, no spaces) and must not collide case-insensitively — `verify.py` block 4a enforces this; dev machines should have `core.ignorecase false` so case-only renames don't slip by git
  - `fav: true` marks a "recommended" item
- `tools/verify.py` is the source of truth for data integrity. After ANY change to `js/data.js`, `js/i18n.js`, `js/app.js`, `js/film.js`, `js/common.js`, `index.html`, `css/style.css`, `tools/lib.py` or `tools/gen_pages.py`, run it (and re-run `tools/gen_pages.py` when its template/data changed). Output must end with `✅ All good` (no errors).
- The theme head-script, the Metrika snippet in `index.html`/`404.html`, the no-JS catalog block in `index.html`, plus the derived files `js/catalog.js` and `js/*.min.js` are generated by `tools/gen_pages.py` from single sources (`gen_pages.THEME_SCRIPT`, `gen_pages.METRIKA_SCRIPT`, `gen_pages.index_noscript`, `js/data.js`, the `.js` sources) — never edit them by hand, re-run the generator instead.
- Page slug = `<imdbId|kp-<kpId>>-<title-en-slug>`; editing `titleEn` renames the URL, so treat `titleEn` spelling as permanent.
- `js/data.js` is grouped by type in blocks: `movie` → `documentary` → `series`. Keep records in their block.
- Do NOT add code comments unless the user asks for them. All comments and docstrings must be in English (RU text is allowed only in data/content strings — titles, descriptions, i18n translations).
